# ERP-система для Московского зоопарка (сборка на Gradle)

Консольное приложение для учета животных и инвентаря в зоопарке, разработанное с применением принципов SOLID и Dependency Injection. Сборка проекта осуществляется с помощью **Gradle**.

## Идеи и принятые решения

В основе архитектуры лежат принципы SOLID, что делает систему гибкой, расширяемой и поддерживаемой. В качестве DI-контейнера используется **Google Guice**.

### Применение принципов SOLID

* **S (Single Responsibility Principle — Принцип единственной ответственности)**
    * `VeterinaryClinic`: Отвечает **только** за проверку здоровья животного.
    * `Zoo`: Отвечает **только** за управление коллекцией животных и инвентаря.
    * `ConsoleApplication`: Отвечает **только** за взаимодействие с пользователем через консоль.

* **O (Open/Closed Principle — Принцип открытости/закрытости)**
    * Система **открыта для расширения**: можно легко добавить новый вид животного (например, `class Elephant extends Herbo`), не изменяя существующий код в классе `Zoo`.

* **L (Liskov Substitution Principle — Принцип подстановки Барбары Лисков)**
    * Любой объект подкласса (`Rabbit`, `Tiger`) может быть использован вместо объекта базового класса (`Animal`), не нарушая логику программы.

* **I (Interface Segregation Principle — Принцип разделения интерфейса)**
    * Интерфейсы (`IAlive`, `IInventory`, `IHerbivore`) чётко разделены по своему назначению, чтобы классы не реализовывали ненужные им методы.

* **D (Dependency Inversion Principle — Принцип инверсии зависимостей)**
    * Модули верхнего уровня (`Zoo`) не зависят от модулей нижнего уровня (`VeterinaryClinic`) напрямую. Оба зависят от абстракций (`IVeterinaryService`). DI-контейнер **Google Guice** сам поставляет нужную реализацию.

### Применение DI-контейнера (Google Guice)

1.  **`AppModule.java`**: Здесь мы "объясняем" Guice, какой класс использовать, когда требуется реализация определенного интерфейса (`bind(IVeterinaryService.class).to(VeterinaryClinic.class)`).
2.  **`@Inject`**: Аннотация в конструкторе `Zoo` и `ConsoleApplication` указывает, что их зависимости должны быть предоставлены Guice.
3.  **`Main.java`**: В точке входа мы создаем `Injector` и получаем готовый к работе объект `ConsoleApplication`.

## Инструкция по запуску в IntelliJ IDEA

1.  **Клонируйте репозиторий** или создайте проект из этих файлов.
2.  **Откройте проект в IntelliJ IDEA**. IDEA автоматически распознает его как Gradle-проект (благодаря файлу `build.gradle`).
3.  **Дождитесь синхронизации проекта**. В правом нижнем углу появится индикатор прогресса. Если этого не произошло, откройте вкладку Gradle справа и нажмите кнопку "Reload All Gradle Projects".
4.  **Найдите файл `Main.java`** в структуре проекта: `src/main/java/com/zoo/erp/Main.java`.
5.  **Запустите приложение**: кликните правой кнопкой мыши по файлу `Main.java` и выберите опцию **Run 'Main.main()'**.
6.  В нижней части экрана откроется консоль, где вы сможете взаимодействовать с программой.

### Запуск из командной строки (опционально)

Проект настроен с использованием Gradle Wrapper. Это позволяет собирать и запускать проект с правильной версией Gradle, даже если он не установлен у вас в системе.

1. Откройте терминал или командную строку в корневой папке проекта.
2. Выполните команду:
    * На Windows: `.\gradlew.bat run`
    * На macOS / Linux: `./gradlew run`

Эта команда автоматически скомпилирует и запустит приложение.
